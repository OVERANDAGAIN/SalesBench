# V1 验证记录与交付说明

## 打开原型

下载 `SalesBench.html`，用 Chrome / Edge 双击打开即可交互。该文件已内嵌所有脚本、样式和图片；不需要安装依赖、联网或部署。

五页顺序为：排行榜、商品推荐、公共交流、私聊、我的。商品详情及确认购买采用弹窗。

## 实际 JSON 动作与结果

```json
{
  "id": "agent-demo-purchase-001",
  "type": "purchase",
  "payload": {
    "productId": "p1",
    "quantity": 1,
    "expectedUnitPriceCents": 8900
  }
}
```

回执成功：余额从 50000 分变为 41100 分，商品 p1 库存从 8 件变为 7 件，本人新增 1 笔订单。商家松间生活的模拟累计成交额相应增加 8900 分。此示例在独立测试会话运行；交付网页首次打开仍从 ¥500 初始余额开始。

## 可点击流程

1. 排行榜 → 松间生活的「逛逛这家」→ 商品详情 → 公开交流 → 输入问题并发送 → 查看商品 → 购买此商品 → 确认购买 → 我的购买历史。
2. 商品推荐 → 声屿数码商品详情 → 私聊商家 → 输入问题并发送 → 查看商品 → 购买。
3. 商品推荐 → 直接购买 → 确认购买 → 继续浏览。
4. 商品详情或购买确认 → 暂不购买 → 继续浏览，余额保持不变。
5. 购买确认调整数量，查看不足余额或超库存提示。

浏览器实际路径：商品推荐 → 陶瓷随行杯详情 → 公开提问“杯盖可以拆洗吗？” → 商家预设回复 → 私聊“有优惠吗？” → 商家预设回复 → 购买 → 我的（余额 ¥411、1 笔订单）。随后继续浏览，验证暂不购买；再直接购买一次，余额为 ¥322。其余商家分支与数量边界由内核测试覆盖，未声称逐一完成所有浏览器路径。

## 尚未实现与暂定机制

排名暂按模拟成交额降序，推荐使用固定顺序，商家回复为预设文本；正式实验排序、奖励、心理模型和用户模拟机制均未定义。3 家商家、6 件商品、¥500 初始余额；单页面内存共享，刷新或重新打开会重置，不同标签页彼此独立。

权限实现为本地原型的观察接口边界，不构成生产认证。尚未实现服务端认证、跨浏览器多人同步、持久化、异步队列、商家自主经营、模型调用、正式 user simulator、实验核心集成、真实支付和物流售后。没有 Seller 后台或 Agent 管理 UI。

完整配置与修改位置见 `README.md`。

## 依赖与空间

本次未安装任何依赖，新增依赖占用 **0 B**；无 `node_modules`。复用环境内现有 Node.js、Python 与浏览器工具。原型和源码位于独立工作目录，不涉及用户本机 C 盘安装。

交付 HTML 约 0.17 MiB，源码和交付文件体积以下载文件显示为准。所有项目文件均可通过删除解压目录清理。
